## 真实后端端点级计数（新 dist + 500 局种子库，HTTP 实测）

采集：2026-10-03 01:14–01:16
环境：`PORT=3401 DATA_DIR=/tmp/perf-e2e MEDIA_DIRS=/tmp/perf-bench-media AUTH_DISABLED=1
MAINTENANCE_ON_BOOT=0 node /tmp/run-count.js`（run-count.js = better-sqlite3 shim 补丁 +
在 `prepare()` 出来的 `get/all/run` 与 `exec` 上计数；SIGUSR2 时把「自上次 dump 以来」的次数
写到 /tmp/sql-count.json，用于把一次请求的 SQL 精确隔出来）。
数据：`BENCH_DB=/tmp/perf-e2e/screenplay.db BENCH_FOLDER_ROOT=/tmp/perf-bench-media node
scripts/perf-bench/seed-bench-db.js`（500 局带 3KB 大 TEXT + 1500 条 media；目录真实存在，
避免启动扫描删行）。

单次 `GET /api/games?limit=60`（返回 50 卡 / 34,150 B）：

```
                games 投影  rating_targets  卡片海报  媒体计数   合计
优化前（旧）           1            550        50        50    651
优化后（批量评分）      1              1        50        50    102     −84%
```

* 旧实现的 550 = 排序阶段对全部 500 行各查一次 `rating_targets` + 出页的 50 行再各查一次；
  新实现整表读一次（每局最多一行，表很小），排序与出页共用同一个 Map。
* 响应字节数、条数（50）与请求耗时（0.010–0.016 s）前后一致（未插手工评分时两次都是 34,150 B；
  插入两行手工评分后是 34,183 B，差值只来自新增的 `metacriticReleaseDate` 字段）；`game_posters`、`media COUNT(*)`
  仍是每张出页卡片各一条（只为自己真正渲染的那一页付费，这是有意保留的）。
* 手工评分优先级（批量路径）逐条核对：`Game 0` → 99 / source `metacritic`；
  `Game 1` → 77 / source `metacritic-SWITCH`；无手工行的一律回落到 `ratings` 里的自动分。
