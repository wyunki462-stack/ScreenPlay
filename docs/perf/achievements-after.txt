# 成就抓取基准 · after（优化后）· ScreenPlay 1.3.3 服务端
#
# 复现（仓库根目录，先 npm run build）：
#   node backend/scripts/verify/steam-achievements-bench.mjs --mode=after --n=30 --delay=250 --ttl-check --assert-ttl
#
# 口径（脚本内钉死，不依赖「跑的时候代码改到哪一步」）
#   before = 改动前的语义：POST /api/games/refresh-all?achievements=force（每轮无条件重抓成就）
#            + CRAWLER_MIN_INTERVAL_STEAM_MS=1200（= 改动前的生产默认值，也等于全局默认值）
#   after  = 新语义：POST /api/games/refresh-all（默认按 15 天 TTL 复用成就）+ Steam 专用间隔 350ms
#   两轮跑的是**同一份构建**（1.3.3），只有请求节奏与 TTL 口径不同，因此差值即本次优化的收益。
#
# 环境：离线双桩（store 127.0.0.1:4610 / api 127.0.0.1:4611，两个 origin，每请求注入 250ms 延迟），
#       后端 127.0.0.1:4522，AUTH_DISABLED=1，STEAM_API_KEY 为假值，N=30 个游戏（各 1 个 Steam 绑定，无 DLC）；
#       CRAWLER_MIN_INTERVAL_MS=25 仅用于屏蔽与本次改动无关的 HLTB / Metacritic 请求。
#       sweep1 = 首次全量抓取；sweep2 = 紧接着对同一库再点一次「刷新全部」（真实世界最常见的场景）。
#
# 结果（机器可读行）
# PARAMS mode=after n=30 delay_ms=250 dlc=0 steam_interval_ms=350 global_interval_ms=25 achievements=ttl stub=steam-stub-v1 at=2026-10-04T16:00:33.357Z
# BENCH after total_ms=21801 reqs=90 api_reqs=60 p50_ms=2173 n=30 delay_ms=250 dlc=0 steam_interval_ms=350 achievements=ttl store_reqs=30
# BENCH2 after total_ms=16989 reqs=30 api_reqs=0 p50_ms=0 achievements=ttl
# BENCH_TTL after repulled_5000=true skipped_5001=true api_reqs=2 total_ms=14936 ok_rows=30 pass=true
# BENCH_TTL_DETAIL 期望：失败且新鲜 ⇒ 重抓；ok 且新鲜 ⇒ 跳过；全库只应有 1 个游戏重抓（2 个 api 请求）
#
# 内联摘要
#   sweep1 total=21801ms reqs=90 (store=30 api=60) p50=2173ms games=30
#   sweep2 total=16989ms reqs=30 (store=30 api=0) p50=0ms games=0
#   ok 落库：achievements=150 行，achievements_status='ok'=30，last_achievements_refresh 非空=30
#
# 请求数
#   sweep1 90 = store 30 + api 60（总量与 before 相同：间隔与游戏内并行只缩短时间，不减少请求）
#   sweep2 30 = store 30 + api 0（成就阶段整体按 15 天 TTL 复用，api 请求 60 → 0）
#
# 与 before 的对比（docs/perf/achievements-before.txt，同 N=30 / 同延迟 250ms）
#   sweep1  72139ms → 21801ms  3.31×   请求数 90 → 90
#   sweep2  71868ms → 16989ms  4.23×   请求数 90 → 30（成就请求 60 → 0）
#   单游戏 p50 8867ms → 2173ms  4.08×
# TTL 断言：repulled_5000=true（failed + 新鲜 ⇒ 必须重抓）、skipped_5001=true（ok + 新鲜 ⇒ 必须跳过）、
#   api_reqs=2（全库只有被标记 failed 的那 1 个游戏重抓）⇒ pass=true。
#   after 模式下断言失败会让脚本退出码非 0，所以这条 pass=true 是硬门禁。
