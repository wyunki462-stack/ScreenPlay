# 成就抓取基准 · before（改动前语义）· ScreenPlay 1.3.3 服务端
#
# 复现（仓库根目录，先 npm run build）：
#   node backend/scripts/verify/steam-achievements-bench.mjs --mode=before --n=30 --delay=250 --ttl-check --assert-ttl
#
# 口径（脚本内钉死，不依赖「跑的时候代码改到哪一步」）
#   before = 改动前的语义：POST /api/games/refresh-all?achievements=force（每轮无条件重抓成就）
#            + CRAWLER_MIN_INTERVAL_STEAM_MS=1200（= 改动前的生产默认值，也等于全局默认值）
#   after  = 新语义：POST /api/games/refresh-all（默认按 15 天 TTL 复用成就）+ Steam 专用间隔 350ms
#   两轮跑的是**同一份构建**（1.3.3），只有请求节奏与 TTL 口径不同，因此差值即本次优化的收益。
#
# 环境：离线双桩（store 127.0.0.1:4610 / api 127.0.0.1:4611，两个 origin，每请求注入 250ms 延迟），
#       后端 127.0.0.1:4522，AUTH_DISABLED=1，STEAM_API_KEY 为假值，N=30 个游戏（各 1 个 Steam 绑定，无 DLC）；
#       CRAWLER_MIN_INTERVAL_MS=25 仅用于屏蔽与本次改动无关的 HLTB / Metacritic 请求。
#       sweep1 = 首次全量抓取；sweep2 = 紧接着对同一库再点一次「刷新全部」（真实世界最常见的场景）。
#
# 结果（机器可读行）
# PARAMS mode=before n=30 delay_ms=250 dlc=0 steam_interval_ms=1200 global_interval_ms=25 achievements=force stub=steam-stub-v1 at=2026-10-04T15:56:09.533Z
# BENCH before total_ms=72139 reqs=90 api_reqs=60 p50_ms=8867 n=30 delay_ms=250 dlc=0 steam_interval_ms=1200 achievements=force store_reqs=30
# BENCH2 before total_ms=71868 reqs=90 api_reqs=60 p50_ms=8980 achievements=force
# BENCH_TTL before repulled_5000=true skipped_5001=false api_reqs=60 total_ms=72158 ok_rows=30 pass=false
# BENCH_TTL_DETAIL 期望：失败且新鲜 ⇒ 重抓；ok 且新鲜 ⇒ 跳过；全库只应有 1 个游戏重抓（2 个 api 请求）
#
# 内联摘要
#   sweep1 total=72139ms reqs=90 (store=30 api=60) p50=8867ms games=30
#   sweep2 total=71868ms reqs=90 (store=30 api=60) p50=8980ms games=30
#   ok 落库：achievements=150 行，achievements_status='ok'=30，last_achievements_refresh 非空=30
#
# 请求数
#   sweep1 90 = store 30 + api 60（每游戏 1 次 appdetails + 2 次成就接口）
#   sweep2 90 = store 30 + api 60（force 口径：成就每次全部重抓）
#
# 与 after 的对比（docs/perf/achievements-after.txt，同 N=30 / 同延迟 250ms）
#   sweep1  72139ms → 21801ms  3.31×   请求数 90 → 90（总量不变，收益来自间隔与游戏内并行）
#   sweep2  71868ms → 16989ms  4.23×   请求数 90 → 30（成就请求 60 → 0）
#   单游戏 p50 8867ms → 2173ms  4.08×
# TTL 断言说明：before 模式下 bench 走 force 口径，「ok 且新鲜」的游戏也会被重抓，
#   所以 pass=false 是**预期结果**（本轮断言的作用是证明 after 的 pass=true 不是空跑）。
